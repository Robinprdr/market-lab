## Contrainte déterminante : IB Gateway

L'[installation officielle](https://www.interactivebrokers.com/en/trading/ibgateway-latest.php) existe pour Linux x86_64 et ARM64. IB Gateway est moins gourmand que TWS, mais l'[API socket IBKR](https://interactivebrokers.github.io/tws-api/initial_setup.html) suppose que TWS ou Gateway soit lancé et authentifié. La documentation IBKR indique que le lancement totalement headless sans GUI n'est pas officiellement pris en charge. Une VM Linux peut fournir un affichage virtuel, mais cela ne supprime pas l'authentification ni les contrôles de sécurité. Le redémarrage automatique quotidien est possible certains jours ; l'authentification doit être renouvelée après la réinitialisation hebdomadaire du samedi/dimanche. Une coupure réseau, un reboot ou une demande 2FA peut également exiger une action humaine. Voir aussi les [limites officielles sur le lancement et la connexion](https://interactivebrokers.github.io/tws-api/third_party.html). Aucune des options ci-dessus ne garantit donc une exécution IBKR sans surveillance 24/7.

Avant tout déploiement : mesurer la RAM réelle de Gateway, tester la reconnexion et la 2FA en Paper, définir un superviseur de processus, des sauvegardes SQLite cohérentes, une horloge NTP, une surveillance des déconnexions et une politique d'intervention manuelle. Ne jamais exposer le port API IBKR ou le dashboard sur Internet ; utiliser un accès distant privé. Le bot doit rester en DRY_RUN jusqu'à une validation distincte. Cette étude ne donne aucune autorisation d'ordre Paper ou live.
